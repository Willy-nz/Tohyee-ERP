# Tohyee 0.48.0

Everything merged since 0.47.0: a backup server at a second place (#111 to #115).

## Before you update

- **Database changes:** none.
- **Nothing changes unless you set it up.** Backups stay nightly, and every server stays a main server, until a server admin chooses otherwise.
- **Not yet tried on two real computers.** The backup server is covered by tests only: no real second computer, no real synced folder, no real-sized books, and no switch-over with people waiting. Practise a switch-over before relying on it, and keep your ordinary backups and recovery kit as they are.
- **A mistake or ransomware is copied to the backup server too.** It protects against a lost computer (fire, theft, flood, a dead disk), not a bad entry. The older backups (14 days, 12 months) still matter.
- **Up to an hour of work can be lost** at a switch-over, with hourly backups.
- **Update both servers together.** A backup server on an older version can't open the main's newer backups, and says so.
- **Not yet reviewed by the owner:** the details in BKS1-BKS22 in `docs/ACCOUNTING-EXAMPLES.md`.
- **Releases aren't signed yet**, and Update now is **not yet tried on a real Windows computer** (see the 0.46.0 notes).

## New

- **A backup server at a second place** (`docs/BACKUP-SERVER.md`). Two Tohyee servers: the main one everyone uses, and a second one at another address that keeps a copy and can take over if the main is lost. The two never talk to each other: a folder that syncs between them is all they share.
  - **Hourly backups** (Server › Backups, "How often"): every hour instead of every night. The newest 24 are kept as well as the usual 14 days and 12 months.
  - **Backup server mode** (Server › Backup server, on a fresh install): given the main's recovery kit and the synced folder. It takes no changes, runs no automatic jobs, and only server admins can look at it. Every page says it's a backup copy.
  - **Keeping the copy up to date:** every 5 minutes it looks for newer backups. Each is restored beside the copy in use, checked, then swapped in; a backup that can't be restored leaves the last good copy in place. People, passwords, two-step codes and memberships follow the main. It holds the main's organisations and no others: one removed on the main is archived for 30 days, then deleted.
  - **Each server knows about the other:** the main's Backups page shows what the backup server last took, and each emails its server admins when the other goes quiet (3 hours with hourly backups, 30 with nightly).
  - **Switching over** is always a person's call. A server admin, or an organisation's Owner, types their password again, says why, and confirms the old main is off. The backup server becomes the main and every organisation's automatic jobs come on. It's recorded in the audit trail, with the time each copy was as at.
  - **An old main that comes back** finds a note in the backups folder and stops: no changes, no jobs, books still readable. It can be paired as the backup server, and switching back is the same switch the other way. If the switch was a mistake, a server admin presses "This is the main server after all".
  - **The offer to switch:** given the main's outside address, the backup server asks it every 5 minutes and emails server admins after 15 minutes without an answer. Saying nothing changes nothing.
  - **Practise a switch-over:** checks every copy opens, the note can be written and the outside address answers, without switching. The page reminds you every 6 months.
  - **From the command line:** `npm run admin -- backup-server status`, `pair`, `refresh`, `main-address`, `practise`, `make-main` and `main-after-all`.

## Not built

- A page for the backup server in the Windows server app: use the web Server pages on the server computer, or the command line.
- Moving the outside address from one server to the other at a switch-over: it's done by hand.
- Not carried over at a switch-over: AI and app connections, sign-in sessions (people sign in again), and groups of organisations for combined reports with their chart mapping. Server settings such as email are set up on the backup server itself.
